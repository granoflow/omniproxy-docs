# 常见问题

## 我需要换掉现在的聊天或编程工具吗？

不一定。工具支持自定义服务地址、认证和模型协议时，可以继续使用。先按[接入指南](17-tools.md)完成一个小任务，再验证工具调用、图片等高级能力。

## 本地处理是否意味着所有数据都不离开电脑？

只有实际由本机模型处理的相应内容在本机执行。你主动选外部模型、搜索、远程翻译或 MCP 服务时，会向对应服务发送所需内容。不要只因为开着 OmniProxy 就认为所有请求都是本地的。

## 为什么已经有模型文件，还是不能调用？

文件存在、格式受支持、模型能加载和任务实测是不同条件。检查[本地模型](05-local-models.md)状态、目录授权和调用测试，不能只把文件复制到目录里就认为已完成。

## 为什么同名模型出现在两个来源里？

两个供应商可以提供同名模型，也可能使用不同权限或协议。使用明确目标或[用途映射](model-mapping.md)，不要让工具只填一个有歧义的裸名称。

## 开启脱敏后还能发送私人材料吗？

规则可能漏检，媒体内容也不自动等同于文本保护。先用虚构数据测试、查看实际范围，再按材料性质决定是否使用外部服务，见[脱敏指南](11-redaction.md)。

## 词表没有生效怎么办？

检查语言方向、本次词表模式、是否命中原文、后端是否支持词表，以及严格术语结果。保存词条成功不等于任何翻译引擎都会采用它。

## App 和 CLI 为什么看见的来源或记录不同？

先核对程序路径、版本与独立 CLI 是否使用自定义数据目录。独立 CLI 的来源和记录不自动等于当前 App 的内容；管理 App 使用 App 页面，管理独立 CLI 使用固定程序与目录。不要把 App 私有目录交给 CLI，也不要为了让列表一致复制数据库或凭据文件。

## 为什么某条 CLI 命令有帮助但执行说不可用？

当前包可能只提供了命令合同或部分实现。看错误码、版本和本地帮助；不要把预演结果、帮助文字或 AI 建议当作实际执行成功。

## 卸载 App 会删除模型吗？

只把 `OmniProxy.app` 移到废纸篓，不等于清除数据：设置、调用记录、系统凭据库中的凭据，以及 App 外的模型文件不会因为应用文件被移除就一并消失；供应商账号和订阅也不会被取消。

正式数据移除的 `private` 范围针对当前发行物私有状态与凭据；`all` 范围只增加经确认属于该发行物的专有内容。用户原始文件、其他工具共享的模型、归属不明的旧内容不应因此删除，Apple 系统模型也不由 OmniProxy 卸载。具体对象以移除预览的逐项清单为准，不凭文件夹名字手动清空。

独立 CLI 可以先用 `omniproxy data remove --help` 阅读当前支持项，再用 `omniproxy data remove --scope private --dry-run --output json` 只预览；它预览的是 CLI 所属数据，不是当前 App。不要为了卸载 App 执行 CLI 的删除命令。当前 App 若没有可见的数据移除入口，先保留数据并通过“关于”的报告入口咨询，不猜隐藏路径，不把已实现的底层移除能力当作已开放的 App 按钮。

当前 App 没有可见数据移除入口时，只卸载应用可以将 App 移到废纸篓并保留资料；希望同时清除 App 数据时，先通过“关于→报告问题”咨询。此时没有可照做的 App 数据清除预览入口，不用独立 CLI 删除代替它。
