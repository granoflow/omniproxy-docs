# 常见问题解答

## 1. 我需要换掉现在用顺手的聊天或编程工具吗？

不需要。只要你现有的工具支持**自定义服务地址（Base URL）**、**API Key 认证**以及兼容的模型协议（如 OpenAI 或 Anthropic 协议），就可以继续在原来的软件里聊天或写代码。建议先按[接入第三方 AI 工具](17-tools.md)跑通一条简单问答，再逐步验证图片识别或工具调用等高级功能。

## 2. 使用 OmniProxy 是否意味着我所有的数据都不会离开电脑？

**不是**。只有当你明确选择并调用**本地模型**时，推理计算才完全在你的电脑上完成。一旦你主动选择了**远程云端模型、网络搜索、网页读取、远程翻译引擎或远程 MCP 服务**，你的请求内容就会发送给对应的外部服务商。请勿认为只要在电脑上开着 OmniProxy，所有请求就都变成了纯本地处理。

## 3. 为什么磁盘里已经有模型文件了，还是不能调用？

“磁盘上有模型文件”、“文件格式受引擎支持”、“当前硬件能成功加载模型”以及“模型能正确完成你的具体任务”是四个层层递进的不同条件。请打开左侧**本地模型**检查该模型的状态、目录访问授权，并务必完成一次真实的**调用测试**并点击**加入代理**（详见[下载与管理本地模型](05-local-models.md)），不能仅凭把文件拷进了文件夹就认为配置已经完成。

## 4. 为什么同一个模型名称会同时出现在两个不同的来源里？

不同的云端供应商完全可能提供同名模型（例如都叫 `qwen3` 或 `gemma3`），但它们背后的账号权限、计费价格或协议细节可能并不相同。遇到跨来源同名模型时，不要在外部工具里直接填写有歧义的裸名称；请前往[用固定名称映射模型](model-mapping.md)，将特定来源下的特定模型明确绑定到 `chat` 等固定用途名称上，让工具统一调用无歧义的映射入口。

## 5. 开启“发送前文本脱敏”后，就可以放心把机密材料发给外部服务了吗？

**不能掉以轻心**。首先，任何脱敏规则与本地复核模型都存在漏检的可能；其次，文本脱敏规则不会自动保护图片、音频、视频等二进制媒体文件。在发送重要材料前，请务必先用虚构数据在[设置发送前文本脱敏](11-redaction.md)页面测试实际替换范围，再根据材料的敏感程度审慎决定是否使用外部云端服务。

## 6. 我已经在“词表”里保存了术语，为什么翻译出来还是没生效？

保存词条成功仅代表术语已写入本地词表。如果翻译时未生效，请依次检查：
1. **翻译**工作区选择的源语言/目标语言方向是否与词表一致。
2. 本次任务的词表选择器是否误选了“不使用词表”。
3. 输入的待翻译原文拼写是否确实命中了该词条。
4. 当前选用的翻译后端是否支持消费词表（部分专用翻译接口不支持词表，系统会明确报错而不会伪装成功）。
5. 完整排查步骤请参阅[管理词表与使用翻译工作区](10-glossary-translation.md)。

## 7. 为什么桌面端 App 和命令行 CLI 看到的来源或调用记录不一样？

因为**桌面端 App** 与**独立 CLI** 拥有各自独立的数据目录与状态边界（此外，独立 CLI 还可以通过 `--data-dir` 指定不同的自定义目录）。管理桌面端 App 请直接在 App 窗口内操作；管理独立 CLI 请固定使用同一程序路径与相同的数据目录参数。**切勿把桌面端 App 的私有资料库路径传给独立 CLI，也不要为了让两边列表一致而手动复制数据库或凭据文件**。

## 8. 为什么某条 CLI 命令能打出 `--help` 帮助，执行时却提示不可用？

这说明当前开发版安装包已定义了该命令的参数合同，但底层能力尚未在当前发行物中完全开放（例如返回 `capability_not_ready`）。遇到此类提示时，请以实际返回的错误码和当前版本说明为准；切勿将 `--help` 帮助文本、`--dry-run` 预演输出或 AI 助手的猜测当成功能已经执行成功。

## 9. 卸载桌面端 App 会自动删除我下载的模型和配置数据吗？

**不会**。在 macOS 中直接把 `OmniProxy.app` 拖进废纸篓，只会移除应用程序本体：你的本地配置、历史调用记录、保存在 macOS 系统凭据库中的密钥凭据，以及存放在 App 包之外的模型权重文件都不会随之消失；你在各个上游云端供应商开通的账号和付费订阅更不会因为卸载了本地 App 而自动取消。

关于彻底清理应用数据的规范说明：
- **理解正式的数据移除范围**：在 OmniProxy 的数据清理机制中，`private` 范围仅针对当前发行物的私有状态数据与凭据；`all` 范围也只会额外纳入经确认完全归属于该发行物的专有内容。你自己的原始业务文件、与其他软件共享挂载的外部模型文件夹、以及归属不明的历史文件均不会被连带删除；macOS 自带的 Apple 系统模型也不归 OmniProxy 卸载。任何清理动作均以移除预览列出的逐项清单为准，请勿仅凭文件夹名字相似就手动清空磁盘目录。
- **独立 CLI 的数据预览命令**：如果你使用的是独立 CLI，可先运行 `omniproxy data remove --help` 查阅说明，再运行以下命令**仅做清理预览**：

```sh
omniproxy data remove --scope private --dry-run --output json
```

  **注意**：上面这条命令预览和操作的仅仅是**该独立 CLI 实例自身的数据**，绝对不是桌面端 App 的数据。**不要为了卸载桌面端 App 而去终端执行 CLI 的删除命令**。
- **桌面端 App 的卸载与清理建议**：如果当前版本的桌面端 App 界面尚未提供可见的“数据移除”按钮，当你只想卸载软件并保留历史配置与模型时，直接将 `OmniProxy.app` 移到废纸篓即可；如果你希望在卸载 App 的同时彻底清除 App 产生的私有数据，请先保留现状并通过**设置 → 关于 → 报告问题**咨询官方支持渠道，不要自行盲猜隐藏目录手动乱删，也不要拿独立 CLI 的删除命令去代替。
