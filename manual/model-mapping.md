# 按用途映射模型

用途映射给一种任务保留固定名称。例如工具始终请求 `chat`，你在 OmniProxy 把它从模型 A 改到模型 B，工具无需跟着改模型名。任务支持的协议和输入格式仍然必须匹配。

开始前先准备一个能完成目标任务的模型：[连接外部模型](06-external-models.md)或[准备本地模型](05-local-models.md)。来源目录验证和真实能力测试都不能省略。

## 为对话选择目标

1. 打开左侧“模型映射”，选择“按用途映射”。
2. 找到“对话”一行，下面的 `chat` 是这项用途的固定名称。
3. 在第一列选择来源，本机模型选“本地”，外部模型选实际来源。
4. 在第二列选择实际模型。更换来源后重新核对模型，不能沿用另一个来源的同名项。
5. 根据模型可用状态处理所需测试或准入，再开启这一行的开关。
6. 使用行末“测试代理”打开测试窗口，先看顶部的 HTTP 方法、完整地址和请求正文。按用途测试使用该用途提供的调用方案，不是任意改协议的输入框；没有调用方案时会显示不可测试。点击运行后检查响应和错误，再用下面的工具接入步骤发自己的小任务。外部目标的测试会实际外发并可能计费，不是只测连通性。

## 在工具中使用稳定名称

工具仍使用监控台的 Base URL 和代理密钥，把模型 ID 填成已经启用的 `chat`。运行一句短对话后，到监控台确认它解析到刚才的实际模型。

用途名称不是任何协议都能通用的“万能接口”。图片生成要用支持的图片接口，朗读要用对应的语音接口；不能把 `tts` 填进只会文本聊天的工具就得到音频。

| 想完成的任务 | 应核对 |
| --- | --- |
| 对话 | 对话能力及工具实际使用的 Chat / Responses / Messages 等协议 |
| 文生图或图生图 | 对应图像能力、接口及尺寸/图片输入约束 |
| 朗读或转写 | 语音合成或识别能力、音频输入/输出格式 |
| 视频 | 当前可配置的运行路径、所需输入与返回产物 |

页面出现某个用途，不代表已经具备可调用路径。显示限制原因、没有候选或禁止启用时，先按提示处理；不要绕过它来承诺能力。

## 更换后面的模型

先验证新模型，再回到同一用途行修改来源和实际目标。更换绑定后该行会停用；重新核对目标并打开开关，不能以为旧开关会自动保留。工具保留原来的稳定模型名，再运行原来的小任务。监控台应显示新目标，并且返回内容仍满足任务。

本次实测让工具始终请求 `chat`：DeepSeek → Apple 本地模型 → DeepSeek，每次切换目标后重新开启该行，再发送同一句短问候请求；本地和切回后的远程请求均返回 `Hello!`，记录中的实际模型相应变更。

更换模型可能改变费用、数据外发、延迟和能力范围。尤其从本地换到外部来源前，确认该来源的[脱敏策略](11-redaction.md)和计费。

本次将 `chat` 绑定到 DeepSeek 并启用后，用 `chat` 请求 `Reply exactly: Mapping connection successful.`。网关实际外发模型为 `deepseek-flash`，HTTP 200，回答为 `Mapping connection successful.`。检查调用详情里的“请求模型”和“实际模型”，比只看开关更能确认映射生效。

## 为工具已有名称配置模型虚拟

“按用途映射”使用 `chat` 等用途名；“模型虚拟”保留工具原来请求的具体名称。先确认工具发送的完整模型名和协议，然后：

1. 在“模型映射”切换到“模型虚拟”，找到该名称对应行及协议分组。找不到时，使用相应 ChatGPT 或 Claude 分组标题旁的加号“添加模型”，输入工具将请求的名称。名称不能重复、含空白或 `/`，最多 200 字节；不能把任意带斜杠的完整 ID 都当作可新增的虚拟名称。
2. 在该行先选模型来源，再选实际模型。候选显示不可用或需重新测试时，回来源或模型页修复，不靠改虚拟名称绕过。
3. 等待绑定保存，开启该行开关，使用“测试代理”检查请求与响应。这里仍要匹配所处协议分组，不把 OpenAI 名称绑定理解为已经支持另一协议。
4. 工具继续发送该虚拟名称，跑原来的小任务，到监控台核对实际目标。改名后工具须同步改名；删除虚拟映射只删除该名称和绑定，模型文件与订阅仍保留。

## 配置自动匹配

“自动匹配”的请求模型名为 `auto-chat`。它按你给出的候选顺序判断适合当前任务的模型，不会因为普通模型名称有歧义就自动替你挑选。

1. 在“模型映射”切换“自动匹配”。在“添加候选”选择实际目标并点击旁边加号，用上下箭头调整优先顺序。
2. 核对“内容处理”。“仅本地处理”只使用允许的本地目标；多个候选需要云端判断时不能在此模式下启用。只有一个合格候选时直接使用。
3. 有多个候选时，选择可用的“判断模型”，并明确接受“允许外发”带来的内容外发。即使最终选中本地模型，任务内容也会发给判断模型；不愿接受时不要启用这一配置。
4. 打开“启用自动匹配”，点“保存”。提示候选不合格、判断模型不可用或配置未保存时，先解决对应提示。
5. 在“测试任务”输入一项具体任务，点“测试选择”，检查“选中模型”和耗时。此操作只测试选谁，不调用最终模型；判断阶段本身仍可能外发并产生费用。
6. 工具使用 `auto-chat` 发一次真实任务，再到监控台确认最终执行模型与返回内容。修改候选、顺序或判断设置后重新保存、测试。

让 AI 帮你查询和修改现有配置，见[AI 操作指南](18-agent-capability-discovery.md)。
