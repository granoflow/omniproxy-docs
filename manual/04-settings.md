# 系统设置、模型存储与日志

打开左侧导航栏的**设置**。你可以根据当前需要调整界面偏好、管理本地模型的磁盘位置或开启实验功能，无需在第一次调用模型前把所有开关都改动一遍。

## 1. 语言、外观与启动行为

- **界面语言与外观**：“界面语言”支持跟随系统或手动指定语言；“外观”支持跟随系统、浅色或深色模式。切换后可即时预览界面文案与布局，已配置的模型来源和路由不会因界面语言变化而受影响。
- **开机自启与窗口行为**：“开机自启”控制登录系统后是否自动启动应用；“启动时隐藏窗口”控制启动时是否直接收起主窗口。
- **显示推荐动画**：仅控制界面推荐区域的动效展示，不改变任何模型选择或网关调用能力。

> **分清“关闭窗口”、“暂停代理”与“退出应用”**：
> - 直接关闭主窗口或开启“启动时隐藏窗口”，**不会**停止后台网关服务。
> - 如果只想暂时拦截新的代理请求，请前往[监控台](02-monitor.md)点击**暂停代理**（注意：暂停不会取消网关已经受理并正在处理的请求）。
> - 如果需要彻底退出整个桌面端应用及后台 Runtime，请使用顶部应用菜单的**退出 OmniProxy**（快捷键 `⌘Q`），切勿将关闭窗口当作退出程序。

## 2. 模型存储与目录迁移

在“模型存储”区域，OmniProxy 将模型目录分为两类，它们对磁盘文件的操作逻辑完全不同（完整使用流程参见[下载与管理本地模型](05-local-models.md)）：

- **默认下载位置（受管模型存储）**：由 OmniProxy 直接管理的模型库目录，也是所有新下载模型的写入位置。
- **更多模型文件夹（外部已有目录）**：仅用于登记你电脑上其他工具已下载的模型文件夹。OmniProxy 会在原路径直接识别这些文件，**不会**自动复制或搬移其中的文件；从列表中移除目录登记也**不会**删除你磁盘上的原始文件。

### 更改默认下载位置并迁移存储

如需将 OmniProxy 管理的模型库迁移到更大容量的分区、移动硬盘或 NAS：

1. 确保目标外置存储已正常连接，点击“默认下载位置”旁的**更改位置**图标，在系统弹窗中选择并授权新目录。
2. 仔细阅读“迁移模型存储”确认框中展示的目标路径、当前可用空间与预计剩余空间（若无法确认磁盘容量，系统会明确询问，不会把未知容量当成空间充足）。
3. 确认无误后点击**开始迁移**。系统会等待当前运行中的模型释放、暂停新的模型写入，并在完成文件复制与新位置校验后才正式切换路径；若迁移中途失败，将继续沿用原位置。

> **迁移过程中的不可逆边界与异常处理**：
> - **开始后切勿强行中断**：迁移确认框中的**取消**按钮仅用于在点击“开始迁移”前放弃选择。一旦开始迁移，页面上没有中断按钮，请耐心等待执行结果，**切勿通过强制退出应用或拔掉移动硬盘来强行中断**。
> - **出现“旧副本清理待完成”时不要手动删盘**：旧目录中的副本会在新位置校验并切换成功后由迁移流程自动清理。如果界面提示“旧副本清理待完成”，代表新位置已成功切换，但旧文件收尾尚未完成。此时请保留现场，通过**关于 → 报告问题**提交错误信息与迁移目标路径，**切勿自行手动清空仍在使用或未确认的目录**，更不要把“更多模型文件夹”里其他软件的模型当成旧副本删掉。
> - **隐私提醒**：“显示模型文件位置”开关决定是否在模型名称下方展示本地绝对路径。如果你开启了该选项，在截图分享或提交故障报告前，请先抹除路径中包含的个人用户名或业务文件夹名称。

## 3. 日志总量上限

在“日志”区域可以调整调用记录占用的磁盘总量上限（单位为 MB）：

- 调小上限有助于节省磁盘空间，但较早的调用记录及请求/响应正文会更早被自动清理。
- **清理不可逆**：已经被清理掉的历史请求正文无法找回，**调大日志上限并不能恢复此前已清理的正文**。
- 当旧记录的详细正文被清理后，[看懂用量与缓存统计](03-statistics.md)中的历史汇总数字仍可继续保留。对外分享任何日志前，请务必检查并剔除其中的业务原文与附件信息。

## 4. 实验功能：MCP 与浏览器内置模型

- **启用 MCP**：“MCP”属于实验功能，默认关闭。开启后，左侧导航栏才会出现[MCP 服务](mcp-services.md)入口。是否将其投入日常工作流，请结合当前版本的协议支持范围评估，不要因为打开了总开关就默认所有远程 MCP 服务均已完美兼容。
- **允许 Chrome / Edge 模型接入**：控制是否桥接浏览器内置的本地模型，默认关闭。如需使用：
  1. 在设置中开启该开关，并在 Chrome 或 Edge 浏览器的配套扩展中启用 OmniProxy 连接。
  2. 等待设置页状态显示为**扩展已连接，模型可用**，随后前往左侧**本地模型**查看对应条目并完成调用测试。
  3. **状态排查**：若显示“等待浏览器扩展连接”，说明仅打开了 App 开关但浏览器端尚未连通；若显示“分享已关闭”或“模型不可用”，请先在浏览器及扩展端恢复运行条件。
  4. **安全提示**：此功能依赖配套浏览器扩展与浏览器内置模型同时就绪，并非打开开关就能凭空获得任意本地模型。如果当前界面提示**“扩展商店链接尚未提供”**，说明官方尚未开放正式扩展安装包，此时请保持该开关关闭并改用其他已验证模型，**切勿根据名称自行搜索或安装来历不明的第三方浏览器扩展**。

## 5. 版本信息、隐私政策与问题报告

在“关于”区域可以查看当前应用的准确版本号、打开产品手册，或点击**报告问题**生成诊断材料。提交问题时，请附上版本号、复现步骤与已剔除敏感信息的报错内容，切勿直接夹带上游 API Key 或未脱敏的业务原文。关于数据处理的法律边界，请查阅独立的[产品隐私政策](https://github.com/granoflow/omniproxy-docs/blob/main/docs/omniproxy-privacy-policy.md)。
