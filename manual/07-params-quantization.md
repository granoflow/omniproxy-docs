# 07 · 模型参数与量化

选择本地模型时，先区分两件事：下载的是哪一份模型文件，以及这份文件在你的设备上能做什么。模型名称、运行时和量化标记可以帮助你辨认文件，但不能代替一次实际调用测试。

## 看懂模型列表里的标记

「本地模型」列表会展示模型的运行时与已知量化信息。量化描述模型权重的数值表示方式；它是模型文件的属性，不是把现有文件即时切换为另一种精度的开关。

| 信息 | 用来判断什么 | 不能据此认定什么 |
|------|--------------|------------------|
| 模型名称与仓库 | 当前选择的是哪一个模型来源 | 名称相似就一定是同一份文件 |
| MLX / llama.cpp | 当前安装使用哪一种运行时 | 另一运行时一定能直接使用这份文件 |
| 量化标记 | 当前文件已知的量化形式 | 下载完成就一定能正常推理 |
| 测试状态 | 当前安装是否经过验证、是否需要重测 | 所有输入类型都已经可用 |

量化信息未知时，列表不会替模型猜一个精度。遇到没有标记的模型，可以先打开它的仓库介绍核对文件说明。

## 下载完成之后还要看什么

例如，你下载了一个想用于对话的模型：文件下载完成后，先看它是否具备对话能力，再从调试入口尝试一段短文本。下载状态回答的是“文件是否已经准备好”，调用测试回答的才是“这份安装能否完成当前任务”。

| 你看到的情况 | 下一步 |
|--------------|--------|
| 已下载，但尚未验证 | 打开调试入口，检查一次真实调用的结果 |
| 自定义调试 | 使用通用 JSON 调试器检查已登记模型，不把模型名称当作能力证明 |
| 测试失败或运行时不可用 | 查看错误原因，处理后重新测试 |
| 需要重测 | 重新验证当前安装，不沿用之前的成功结论 |

选择时优先看当前安装的事实和测试结果，不使用一张固定的“内存大小对应模型”表替所有模型作判断。不同文件、运行时和输入任务需要分别核对。

下载、调试与删除的具体操作见 [05 · 本地模型管理](05-local-models.md)。如果使用的是外部模型，连接与协议配置见 [06 · 连接外部模型](06-external-models.md)。
