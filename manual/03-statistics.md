# 03 · 统计

统计用来比较一段时间内的调用情况，不是逐条调用日志的替代品。遇到某一次失败，先去监控台看那次调用；想知道用量主要来自哪里、网络搜索是否频繁，再选择统计时间范围。

例如，你发现今天请求变多了，可以先看用量按模型的分布，再看本地模型和网络搜索区块。搜索任务与来源调用是两种计数，一次搜索可能调用多个来源，因此不能把两者直接相加当作用户请求数。

## 选择时间范围

顶部提供按日、按周、按月切换。比较两个区间时，使用相同粒度，并留意页面是否提示数据不可用或历史不完整。

没有数据时会显示空状态；部分区块会按可用数据决定是否出现。没有测量结果不等于零用量，不要把空白或不可用提示当作“没有发生调用”。

## 各区块怎么看

| 区块 | 主要信息 | 阅读时注意 |
|------|----------|------------|
| 日志存储 | 日志占用、记录数与清理入口 | 删除逐条日志和查看汇总是不同操作 |
| 用量 | 已记录的输入、输出 token 及模型分布 | 留意未知用量、混合质量或历史范围提示 |
| 本地模型 | 各模型在当前区间的调用情况 | 安装了模型不代表这个区间使用过它 |
| 网络搜索 | 搜索任务与各来源的调用、成功和失败情况 | 一次任务可能包含多次来源调用 |
| 缓存 | 可评估调用中的命中情况与记录的节省量 | 不代表外部服务账单必然按同样幅度下降 |

## 缓存命中率

页面的命中率按以下口径计算：

```text
缓存命中率 = 命中调用数 / 可评估缓存的调用数
```

分母不是不加区分的全部调用。没有可评估记录时，页面不能据此给出有意义的命中率。

命中率高说明统计范围内较多可评估调用命中了缓存；它不证明某个检索来源被调用，也不证明回答质量更高。页面显示的节省 token 是系统记录的缓存指标，不是外部服务的实际账单。

## 参考：统计分组

统计查询的分组包括 `model`、`source`、`protocol`、`retrieval` 和 `cache`。协议分组用于区分调用入口与实际适配器，不应把所有转译都当作额外的厂商调用；检索分组记录外部来源的调用次数、成功/失败及累计耗时，不保存搜索正文。

这些是查询维度，不表示桌面统计页为每个维度都提供独立区块。

## 清理日志前

「清空日志」需要确认。清理逐条日志不会同时清空长期汇总，因此清理后统计中仍可能有历史用量。若要排查某次调用，先完成检查，再决定是否删除它的日志记录。
