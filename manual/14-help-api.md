# 14 · 帮助与 API 文档

查命令参数与排查一次调用，是两类不同任务。参数以当前安装的 CLI 帮助为准；接口调试则要同时检查请求、响应状态和正文。不要仅凭一段帮助回答判断某个模型已经可用。

例如，一个客户端调用失败时，先核对它使用的协议入口和模型名称，再查看响应中的错误信息；需要确认命令参数时，先使用静态帮助，不必安装额外模型。

## 命令行帮助

```bash
omniproxy --help
omniproxy help export --format json
```

第一条查看命令帮助；第二条导出裸 JSON 帮助数组，便于脚本处理。它与其他命令使用的统一 JSON envelope 不同。

静态帮助支持 `en`、`zh-CN`、`zh-TW`、`de`、`ar`，可使用 `--lang <code>` 选择语言。不同语言保留相同命令路径、参数和 operation ID；静态帮助不依赖模型推理。

`--help-ai [问题]` 是解释请求入口，但当前 Runtime 的帮助服务只返回静态回退结果：`source: static`、`used_ai: false`，并带有 `ai_help_unavailable_static_fallback` 提示。不要把它当成已经具备模型回答或可靠引文的帮助助手。该入口还需要可连接的已初始化 Runtime；没有 Runtime 时应先使用 `--help`。

桌面各页面的「?」提供对应说明，不能据此认定所有页面都连接了同一个 AI 对话服务。

## 模型协议入口

| 协议家族 | 常用入口 |
|----------|----------|
| OpenAI | `/v1/chat/completions`、`/v1/responses` |
| Anthropic | `/v1/messages` |
| Gemini | `/v1beta/models/{model}:generateContent`；流式使用 `:streamGenerateContent` |
| Ollama | `/api/chat` |
| 原生任意透传 | `ANY /v1/raw/{deployment}/{upstream_path}` |

前四类入口进行协议归一化和转译；无法无损表达的字段会通过警告说明。原生透传用于需要厂商独占字段的场景，保留请求方法、路径、查询、正文及非逐跳请求头，不把上游正文改写成另一套协议。

归一化入口的错误保留对应协议外形，并附带 `omniproxy.code`、可获得的上游 HTTP 状态与安全错误信息。原生透传保留上游状态和正文。协议转换次数不等于额外发生了一次厂商调用。

## 独立网络搜索

网络搜索使用 `POST /v1/search`，不是模型协议的一部分，也不会自动把结果交给模型。请求按 `engine` 选择唯一已启用、且当前配置已验证的来源，不接受内部来源 ID。

请求字段、脱敏选项、错误情况和 CLI 发行配置差异见 [09 · 网络搜索](09-search-sources.md)。需要网页读取时使用对应来源能力，不把网页读取当作固定引擎搜索。

## 接口调试时检查什么

打开调试界面不会自动发送请求。运行前核对实际 endpoint 或 operation、模型和正文；可编辑 JSON 的入口会先检查格式，响应保持只读。

| 检查项 | 应区分的内容 |
|--------|--------------|
| HTTP 状态 | 命令执行完成与上游请求成功不是一回事 |
| 请求正文 | 实际发送内容与表单草稿可能不同，尤其启用脱敏时 |
| 响应正文 | HTTP 成功也可能缺少所需结果，仍须检查内容 |
| Headers / Metadata | HTTP 响应头与 gRPC 元数据不是同一概念 |
| 错误与警告 | 部分字段未转译、运行时不可用等情况不能忽略 |

界面可复制内容会隐藏凭据字段，但业务正文仍可能包含敏感信息，分享前应再检查。桌面通过本机 Runtime 执行调试；验证公共 HTTP 时由 Runtime 调用本机网关，不由页面直接调用第三方服务。

## 请求扩展与附件

模型请求只处理当前支持的 `omniproxy` 扩展；旧的增强开关不能让 chat 自动执行网络搜索。显式搜索应使用独立搜索接口。

`files` 接收有界的内联 data URI，而不是任意本机文件路径或可供网关联网下载的网址。具体支持格式和错误行为以当前接口合同为准；未解析的二进制内容也不能被当作已经完成文本脱敏。

## 文档和运行时边界

完整手册发布在 [OmniProxy 文档站](https://granoflow.github.io/omniproxy-docs/)。支持在线手册的版本在根 `--help` 显示链接，App 设置中的产品手册入口使用浏览器打开同一站点；这些版本不再提供 `docs path` 或 `docs serve`。旧版本若仍显示 docs 命令，请以其本地帮助为准。

完整手册需要网络，本地 `--help` 无需网络或模型。动态 API 示例、AI 文档检索与初始化自动索引尚未交付。MCP 已退役，Agent 应直接使用 CLI。
