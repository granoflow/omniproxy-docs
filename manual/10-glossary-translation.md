# 10 · 词表与翻译

词表用于保存稳定的术语映射。OmniProxy 随 Runtime 提供一份只读基础词表，用户可以先导出、在本地编辑，再以相同 `glossary_key` 上传完整用户版本，不必从空文件开始。用户词表在当前发行物 Internal State 中生效；换电脑或跨发行物使用时，必须显式导出并导入带 hash 的快照。词表按术语键生效，不是普通文档检索。

例如，你只想改一个术语，也应先导出完整词表，再保留其他条目并修改目标词条。同名导入替换的是整份用户版本，不是追加一行。

翻译工作台的「模型」页只列出本机已就绪的专用翻译模型；下载、暂停和半成品删除在「本地模型」页完成。没有已装项时仍可去模型页安装，也可配置一个对话模型代替翻译模型。

词表页的导入、导出和添加是图标动作；行内来源图标在原文左侧，删除在右侧。

## 内置基础词表与来源

当前生产候选 `omniproxy-base-en-zh-cn`（English → 简体中文）的词条来自
Wikidata CC0 结构化标签：

- 版本：`wikidata-2026.08.11`
- 许可证：CC0-1.0
- 条目数：10
- 文件大小：416 bytes
- SHA-256：`8031a2b98edbafe34b84d900863610348d9aa1a44d4dba607d8fd489442e7dea`

每条映射保留 Wikidata QID 和实体 revision，并由固定来源清单生成 CSV，不由
OmniProxy 或模型临时翻译。Microsoft Terminology Collection 仍是高质量候选，但其
专门许可入口当前无法从有效官方链接完成核验；完成法律复核前不随安装包复制。

内置层始终只读；发行版以后可以带来新的内置 revision，但不会改写或自动合并现有用户覆盖。资产清单与许可证见 `shared/assets/glossary/`。

## 三种模式

| 模式 | 行为 |
|------|------|
| 自动选择 | 按关键词命中数选择本次翻译所用词表 |
| 手动指定 | 固定使用用户选择的词表 |
| 不使用词表 | 本次翻译不挂接词表 |

M10 已交付模式的共享状态与 CLI/gRPC 管理合同。具体翻译适配器只有在支持词表上下文时才能消费所选词表；不支持的后端必须明确提示，不能假装已经应用。System / Guideline 仍可独立配置。

## 导出、编辑和同名覆盖

推荐流程：

1. 导出当前有效版本，或用 `--layer builtin` 明确导出内置版本。
2. 保留 UTF-8 CSV 与固定表头 `SourceTerm,TargetTerm`，编辑需要的映射。
3. 使用同一个 `glossary_key` 导入；Runtime 先完整校验，再原子建立 user revision。
4. 如需撤销整个用户版本，执行 reset，立即回到当前内置 revision。

同名覆盖的单位是整份词表，不逐词条合并。显示名或文件名相同不构成身份；稳定 `glossary_key` 才是覆盖依据。导入另一稳定键会创建另一份用户词表。

## 文件校验

首版只接受 UTF-8 CSV：

- 首行必须精确为 `SourceTerm,TargetTerm`。
- 每条数据必须正好两列，两个值都非空。
- UTF-8 BOM、重复 `SourceTerm`、错误列数和空文件会使整批失败。
- CSV 最大 500 KB；错误会给出稳定错误码和可定位信息。
- 校验或写入任一步失败时，旧 active revision 保持不变。

用户可以使用 Excel、Numbers、文本编辑器或 AI 协助编辑；OmniProxy 不要求文件来自特定厂商，也不会把词表上传到外部服务。

## 用户可见状态

设置页应区分：内置版本、用户覆盖、校验失败和基础资产不可用。上传成功后显示词表名、条目数和当前层；上传失败时保留原版本并显示错误。主要动作是“导出当前词表”和“上传完整词表”，reset 是需要确认的恢复动作。

当前 CLI、gRPC 和共享存储已验证“新 Home 自动出现内置词表 → 导出 → 同名上传整表覆盖 → reset 回退内置”的完整边界。后续 UI 必须调用相同 Core 接口，不自行解析或合并 CSV。
