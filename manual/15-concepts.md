# 几个容易混淆的概念

## 工具、网关和模型来源

工具是你聊天、编程或创作的地方；网关负责接收请求并交给目标；模型来源是真正提供模型能力的本机引擎或外部服务。配置工具的网关地址，不会自动替你准备来源。

## 两种密钥

供应商 API key 交给来源配置，用于访问上游服务；代理密钥交给调用 OmniProxy 的工具，用于访问网关。换了供应商 key 不等于必须更换网关 key，反过来也一样。

## 模型名称、用途和实际目标

完整模型 ID 用来识别目标；用途名如 `chat` 是你配置的固定入口。工具请求 `chat` 时，实际可能运行另一个具体模型，记录与用量按实际执行目标理解。

模型名中的斜杠也可能属于上游完整名称，不要自行截断成最后一段。出现歧义时明确绑定目标，不能认为系统会随便选一个。

## 模型目录与模型位置

模型目录帮助你发现候选；模型位置是磁盘上的实际文件目录。添加已有目录不是联网下载，下载结束也不是实际运行测试。

默认下载位置是当前管理的模型存储，更改它需要确认迁移，验证新位置后才切换。其他模型文件夹用于原地识别已有模型，登记本身不复制文件；是否可运行仍受格式、引擎与实际能力限制。

## 四种不同的“成功”

| 成功发生在哪里 | 还不能单独证明什么 |
| --- | --- |
| 保存配置 | 远程服务可连接 |
| 来源验证读取了目录 | 模型能处理你的真实输入 |
| 一次调用返回成功 | 所有能力、语言、附件和工具都兼容 |
| 统计已有数字 | 原始请求正文仍然保留 |

按自己的任务补上下一层验证。具体流程从[快速上手](01-getting-started.md)开始。
