# 15 · 核心概念

理解 OmniProxy 时，先分清“请求从哪里进来”“由哪个来源执行”和“结果在哪里查看”。兼容某种协议不等于内置了该厂商的软件；下载了一个模型，也不等于所有输入形式都已经验证可用。

例如，客户端使用 OpenAI 格式发起请求，实际执行者可以是你配置的外部服务，也可以是本地模型。排错时应分别检查协议、模型来源和实际响应，而不是只看客户端名称。

## 协议入口与执行来源

| 入口家族 | 本地端点 | 处理方式 |
|----------|----------|----------|
| OpenAI | `/v1/chat/completions`、`/v1/responses` | 归一化后转译 |
| Anthropic Messages | `/v1/messages` | 归一化后转译 |
| Gemini | `/v1beta/models/{model}:generateContent` 与流式变体 | 归一化后转译 |
| Ollama Chat | `/api/chat` | 归一化后转译 |
| 原生任意透传 | `ANY /v1/raw/{deployment}/{upstream_path}` | 按指定来源转发，不进行协议归一化 |

前四个家族共同表示文本、系统指令、工具调用和常用生成参数，再转换为目标来源需要的格式。无法无损表达的字段应通过警告说明。原生透传保留方法、路径、查询、正文、非逐跳请求头和上游状态，适合厂商独占字段；它仍然经过来源选择与认证，不是绕过网关控制的通道。

Ollama 可以是客户端使用的兼容格式，也可以是你自行部署的外部来源。OmniProxy 不替你安装或管理 Ollama；自带本地模型使用 OmniProxy 的推理运行时。

## 模型文件、来源和调用能力

内置签名模型目录固定仓库、revision、许可和文件校验信息。它和临时搜索到的仓库列表不是同一类证据。下载完成后，还需要区分文件状态、可用能力和真实调用结果。

| 概念 | 用来回答的问题 |
|------|----------------|
| 模型目录条目 | 准备获取哪一份模型文件？ |
| 本地安装 | 这份文件是否已下载、校验并可以找到？ |
| 能力与测试状态 | 当前安装能否完成这类任务，是否需要重测？ |
| 外部来源 | 请求发送到哪个服务，使用哪份连接配置？ |
| 模型引用 | 本次请求究竟选择哪个模型？ |

`deployment/model` 表达指定来源中的模型；不带来源前缀的名称需要按当前路由配置解析。排查时查看实际使用的来源，不把两个名称相似的模型视为同一份安装，也不要以过去的成功测试代替当前验证。

不安装本地模型也可以使用已经验证的外部来源。本地文件管理见 [05 · 本地模型管理](05-local-models.md)，量化与测试的关系见 [07 · 模型参数与量化](07-params-quantization.md)，来源配置见 [06 · 连接外部模型](06-external-models.md)。

## 搜索、附件与模型回答

网络搜索由独立 `POST /v1/search` 返回结果。一次请求选择一个搜索引擎，调用方决定是否把结果放入后续模型请求。网页读取则面向明确网址。它们不会因为一次 chat 请求而自动执行，具体选择与验证规则见 [09 · 网络搜索](09-search-sources.md)。

附件是本次请求提供的输入，不是授权网关扫描文件夹。`files` 使用有大小限制的内联 data URI，不接收任意路径或让网关按任意网址下载文件。文本、图片和其他输入还受具体入口及模型能力限制。

同样，模型标记为多模态不代表每种附件都已成功测试。先用小样例验证所需格式，再检查实际结果；不能仅凭 HTTP 成功认定图片或音频已被理解。

## 调试与真实执行

对话和向量调试使用 `models probe-chat`、`models probe-embedding`，由 Runtime 调用正在监听的网关。网关未启动时不能把进程内测试当作这条 HTTP 路径已经通过。翻译调试使用翻译入口；模型健康检查与一次具体内容的调用测试也不是同一件事。

某个入口显示错误或警告时，应按实际结果处理；不要把不支持的字段、无响应或回退结果当成完整成功。更多接口说明见 [14 · 帮助与 API 文档](14-help-api.md)。

## 日志、统计与缓存

监控台通过结构化调用记录和完成事件读取结果，不解析服务进程在终端打印的文本。日志记录一次调用的状态；统计用于比较一段时间内的汇总。两者有关联，但保留时间和清理方式不同。

因此，清理逐条日志后仍可能看到历史统计。日志正文、记录元数据和长期汇总也不是同一份内容；保留设置与磁盘上限应以当前设置为准。统计读法见 [03 · 统计](03-statistics.md)。

答案缓存独立保存加密响应，不直接把日志正文当作缓存。命中率和记录的节省量不是厂商账单，也不表示回答一定准确；缓存认证或解密失败不能降级为明文读取。

## 词表与脱敏

词表决定翻译时采用哪些术语，脱敏决定发往某个外部来源的可解析文本如何处理。两者都应通过各自的设置和测试验证，不靠切换一个全局默认模型代替配置。

内置词表只读，用户版本按同名整表覆盖；恢复默认会移除用户覆盖而回到内置层。迁移覆盖内容使用显式导出与导入，见 [10 · 词表与翻译](10-glossary-translation.md)。

发送前脱敏按外部来源设置，默认关闭。可选复核使用单独选择的本地模型；模型不可用时不会自动换用远程服务。规则覆盖和允许名单的范围、翻译占位符恢复及二进制限制见 [11 · 脱敏](11-redaction.md)。
