# 查看调用记录

当工具给出错误、回答异常或你想知道请求去了哪里时，打开“监控台”。这里先看网关是否运行，再看最近调用。

![监控台的网关连接和最近调用区域](images/zh-CN/gateway-overview.png)

图中“暂无调用记录”表示这个隔离环境尚没有记录。它不是一次调用成功的结果。正常使用时，先从工具发起一个小任务，再回来查找。

## 找到刚才的请求

1. 在 AI 工具里发送一个容易辨认的短问题，记下大致时间。
2. 回到“监控台”，在“最近调用”里找对应时间的记录。
3. 查看成功或失败、耗时及实际模型；打开记录，阅读当前可用的详情。
4. 对照请求和响应：模型是不是你选择的，回答是否非空，错误来自网关还是上游。

同一次工具任务可能包含多条请求。例如工具先请模型规划，再调用工具、补充资料并继续生成。不要只因为记录多了就判断重复计费；先逐条看它们的时间、目标和内容。

![真实调用记录区分请求名称和实际执行模型，显示 HTTP 200 与成功状态](images/zh-CN/monitor-record-success.jpg)

图中是 `logs list` 实际字段摘录的浏览器阅读视图，不是 App 截图。例如请求名称为 `chat`，实际模型为 `deepseek-flash`；HTTP 200 和 `success` 表示这些请求完成。看见相同字段后，仍要打开对应记录核对正文，不只看状态。

## 哪些内容可以从记录判断

| 信息 | 可以帮助你判断 |
| --- | --- |
| 时间、状态与耗时 | 请求何时发生，是否失败，等待大致在哪一次调用出现 |
| 实际来源与模型 | 用途或别名最终交给了谁 |
| 可用的请求详情 | 工具实际发来的消息、参数或附件信息，而非仅工具界面显示的一句话 |
| 可用的响应与错误 | 模型返回了什么，或认证、模型能力、网络等环节出了什么问题 |

记录只包含实际保存和协议允许展示的信息，不代表能看到模型隐藏的思考过程。某些调用没有正文、旧正文已清理或流式响应只完成一部分时，应按详情中的实际状态理解。

## 找不到记录时

先检查工具中的 Base URL 是否就是当前网关，网关是否运行，以及时间范围是否包含这次操作。请求在到达网关前失败、被入口拒绝或没有形成相应记录时，不能单凭空列表断言模型没有工作。

旧记录的正文可能已按保留设置清理；[统计](03-statistics.md)中的汇总可以继续存在。更改时间范围、检查当前发行物和数据实例，避免把独立 CLI 的记录拿到 App 数据里找。

## 暂停代理、复制连接信息

网关连接区域提供运行/暂停入口、地址复制和代理密钥操作。暂停会阻止后续代理请求，不会主动取消已经受理的请求。先让工具中的请求完成，再暂停；已经发出的请求是否完成，仍到调用记录检查，不能把“暂停”当成取消按钮。地址变化后，按[首次接入](01-getting-started.md)重新核对工具配置。

代理密钥与供应商密钥用途不同。在“代理密钥”一行，眼睛图标显示或隐藏当前密钥，“复制密钥”将当前值复制到剪贴板，“生成密钥”会生成并保存新密钥。首次生成与轮换使用同一入口；轮换后更新所有使用旧密钥的工具，再运行小请求确认。不要把含密钥的截图分享出去。

## 分享排错信息

先记录工具版本、时间、所用模型和错误提示，再检查分享内容。删除密钥、个人信息、原始业务文本和附件信息。调用记录可能包含有价值的原文，它不会因为“用于排错”就自动变成适合公开的数据。
