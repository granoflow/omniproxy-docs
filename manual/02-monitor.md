# 02 · 监控台

监控台用来查看网关连接与最近调用。先确认当前连接地址，再检查一次实际调用的状态和结果；页面可打开不等于客户端已经连通。

例如，客户端报告失败时，先在最近调用中找到对应记录，再区分连接、上游错误和响应内容问题。不要仅凭菜单栏图标判断一次调用成功。

## 本地网关连接

监控台顶部显示 `本地网关` 的连接状态。

- **当前 API URL**：主按钮复制当前选择的完整 URL；地址菜单可在 Core 返回的 loopback、Wi-Fi、Ethernet、VPN 和 global IPv6 endpoint 之间切换。选择只改变显示与复制目标，不改变监听范围。
- **监听范围**：默认「仅本机」，同时监听 `127.0.0.1` 与 `::1`；「所有网络接口」同时监听 `0.0.0.0` 与 `::`。
- **密钥前置**：切换到「所有网络接口」前必须设置代理密钥。没有密钥时先打开密钥 sheet；保存成功才切换，取消或失败保持「仅本机」。
- **地址变化**：当前网卡消失或默认路由改变时，界面使用 endpoint 事件自动回退到新的推荐地址并提示用户；IPv6 URL 自动添加方括号。
- **熔断**：来源异常时 `已自动停用：{code} — {text}`，问题解除后恢复。

## 最近调用

区块标题 `最近调用`。没有记录时显示 `暂无调用记录`。App 打开后先用 `LedgerService.ListCalls` 载入最近历史，再接续 `LedgerService.WatchCalls` 的结构化完成事件；因此重启 App 不会丢掉此前的摘要，也不需要解析终端输出。当前摘要行显示完成时间、调用方、实际模型、成功/失败状态和输入/输出 token。

每一行日志包含：

| 字段 | 含义 |
|------|------|
| 状态徽标 | `本地` / `未知` |
| 这次问了什么 | 请求摘要，可展开看 `摘要` |
| 模型回了什么 | 响应摘要 |
| 缓存命中 | `缓存命中` / `检索缓存` / `答案缓存` |
| 命中提示 | 检查本次是否复用了缓存，不把命中当作新的上游生成 |
| 错误来源 | `调用方` / `本地网关` / `上游` |
| 省下的 token | `省 ↓{n}` |

> `（仅保留基础日志）`：当天日志被清理策略裁剪到保留量时，只留基础日志。

监控台读取已保存的调用记录与实时完成事件，不解析终端输出。排查某次调用时使用日志详情或 `omniproxy logs show <call-id>`。

## 日志详情弹窗

点任意一行可展开详情（`详情弹窗`）：

- `这次问了什么`
- `模型回了什么`
- `命中类型`
- `节省 token`
- `完整 JSON`：按正文保留策略读取真正发往上游的最终请求和真正收到的上游响应。凭据字段掩码，但业务正文仍可能敏感，分享前请检查；没有可另行开启的账本文本脱敏功能。
- 成功正文默认保留 24 小时，可改为 6 小时或 3 天；错误正文默认保留 7 天，可改为 30 天或跟随成功策略。正文到期后详情显示 `expired`，安全元数据再保留 30 天。
- `logs watch` / `LedgerService.WatchCalls` 建立连接时先发 `snapshot`，每次调用提交完成后发带递增序号的 `completed`；事件只携带摘要，需要正文时再按 `call_id` 查询详情。

## 监控与统计的关系

监控台的「最近调用」和[统计](03-statistics.md)视图**同源写入**：一次调用提交账本时，在同一个 SQLite 事务中同时累加长期日统计。统计不是临时扫描当前日志算出来，因此正常保留期间可以逐条核对；用户清空日志或正文过期后，长期统计仍保留，不会跟着归零。

## 后台作业

模型下载等跨重启工作记录为 Shared 作业；来源测试、检索验证和账本维护等只属于当前发行物的工作记录为 Private 作业。Desktop 与 CLI 都通过同一个 JobService 查看当前 Runtime 有权看到的作业，但 standalone CLI 看不到 Desktop 的 Private 作业，Desktop 也看不到 CLI 的 Private 作业。列表中的 `scope` 明确标为 `shared` 或 `private`，不会把两者混在一个不可解释的状态里。

作业观察使用结构化 gRPC 事件：先发一次 `snapshot`，状态变化时发 `changed`，进入 `succeeded`、`failed` 或 `cancelled` 后发 `terminal` 并关闭事件流。界面因此可以直接显示进度、错误码和最终状态，不解析 `omniproxy jobs watch` 的终端文本。只关闭观察窗口不会取消作业；取消必须由用户明确执行。

字节型下载同时显示「已完成 / 总量」；只有开始时间、更新时间和非零进度足以形成可靠样本时才估算剩余时间。估算值不是完成承诺，暂停、网络变化或重试后会重新计算；数据不足时不显示假 ETA。
