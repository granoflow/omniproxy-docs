# 设置发送前文本脱敏

脱敏会在文本发给指定外部来源前，按规则识别并替换部分敏感值。它可能漏检，也可能把应保留的内容误判；第一次配置请用虚构数据测试，不直接用真实客户资料验证。

本页处理文本，不表示图片、音频和视频自动获得同样保护。调用记录、截图和导出文件也要单独检查。

## 为一个来源开启策略

1. 先在[远程模型](06-external-models.md)、[网络搜索](09-search-sources.md)或[MCP 服务](mcp-services.md)添加实际来源。
2. 打开左侧“脱敏”，在“按来源发送前脱敏”中找到要使用的来源。
3. 开启这一行的“发送前脱敏”，确认保存状态。
4. 不需要发送原文时，保持“允许请求跳过脱敏”关闭；它允许调用方显式要求这一次跳过处理，不能当作“更严格”的开关。
5. 如果使用另一来源，也要单独检查它的设置；没有总开关替你覆盖所有新来源。

图中是尚未添加来源的配置界面。按来源开启策略后，还需要分别检查本机预览与真实调用；空结果不能当作“没有敏感信息”。

## 用虚构数据检查结果

页面提供“翻译可逆脱敏 JSON 测试”。它检查本机占位符替换与恢复。界面要求先选择可用来源，但此预览本身不调用外部翻译模型，不能据此判断真实网络请求已脱敏。

1. 选择要验证的来源。
2. 从页面示例 JSON 开始，只改其中的测试文本，例如使用 `demo@example.com`，不要粘贴真实联系人资料。
3. 运行测试，查看“处理结果 JSON”和标准规则命中、模型复核及耗时等结果。
4. 核对预览替换了哪些值，处理后的内容是否还包含本应隐藏的原文，以及本机恢复是否成功。
5. 修改规则、来源或输入后重新运行；旧结果不能证明新配置有效。

支持可逆处理的外部模型翻译会为本次请求建立临时占位符，回来后校验并在本机恢复。占位符缺失、重复或异常时应按错误处理，不直接发送原文来“补救”。普通模型/搜索请求与翻译恢复流程不能混为一谈。

测试输入可以从下面的完整 JSON 开始；只替换 `text`，不要改成一个没有引号的普通句子：

```json
{
  "mode": "translation",
  "text": "Contact demo@example.com."
}
```

在这个预览里，`outbound_json` 是准备发送的内容结构，`upstream_json` 回显处理后的内容，并非远端模型的真实回复。`restored_text` 是本机恢复后的文本，`restore_status` 表示恢复状态；`pii_match_count` 是标准规则命中数量，`model_review_ran` 和 `review_incomplete` 分别表示复核是否执行、是否完整。JSON 字符串中的转义不代表原文被保护，应阅读字段的实际内容。结果为空、报错或恢复失败，都不能当成测试通过。

## 再用真实翻译核验外发与恢复

1. 保持目标外部模型来源的“发送前脱敏”开启，并在[模型映射](model-mapping.md)为翻译用途启用该模型。
2. 打开[翻译工作区](10-glossary-translation.md)，选择英语到简体中文，输入虚构句子 `Contact demo@example.com.` 后运行。
3. 在模型调用详情查看实际请求：原邮箱应已换成临时占位符；不要只在最终译文中搜索邮箱，因为译文会在本机恢复它。
4. 检查上游返回仍保留对应占位符，最终译文重新出现 `demo@example.com`；同时确认没有恢复错误。若失败，检查错误和来源策略，不改为发送原文绕过。

本次真实示例的最终译文为“请联系 demo@example.com。”，请求中的原邮箱已被替换，恢复状态为 `ok`。这是这一条测试的结果，不代表其他类型文本或所有敏感信息都能被识别。

## 标准规则与可选模型复核

标准规则由本机引擎处理。“默认规则文档”只读，使用“下载默认规则文档”查阅当前规则 ID；“用户覆盖文档”控制这些已有规则的启停，不是任意正则表达式或程序编辑器。

例如保持邮箱识别开启，可在“手工编辑覆盖文档”中填写以下 YAML 列表，点“应用更改”；也可保存为 UTF-8 `.yaml` 文件后用“上传覆盖文档”导入：

```yaml
- rule_id: pii.regex_email
  enabled: true
```

`rule_id` 必须在当前默认规则目录中；`enabled` 为 `true` 或 `false`。未知 ID 或格式错误会拒绝导入，额外只读字段会被忽略并给出警告，不能靠添加 `pattern` 改写内置匹配方式。先下载现有文档并记下原设置，应用后核对更改项，再用虚构输入重跑测试；恢复时将所改规则设回记录的原值。

“复核模型”只选择当前可用、适合复核的本地模型。不使用模型复核时仍可运行标准规则；选择模型后可能增加等待时间。模型不可用或复核不完整时，检查实际结果与提示，不把“选过模型”当成“这次已经复核”。

“允许名单”保存你确认可以保留的值。打开允许名单管理，输入虚构测试值并点击添加图标，确认条目出现后重跑测试；不再需要时从名单移除，再测试恢复效果。添加真实值前先想清楚它在其他请求中出现是否也可以外发。

“允许请求跳过脱敏”只是允许调用方显式申请跳过，不表示开启后默认跳过；未明确申请的请求仍跟随该来源策略。

## 哪些保证不能从开关推出

- 文本处理不能证明所有敏感值都被识别。
- 为一个模型来源开启策略，不会自动覆盖另一搜索来源。
- 媒体二进制不等于可解析文本，不能从本页承诺媒体内容已保护。
- MCP 须逐连接开启策略，只处理受支持请求中的业务文本；不全面处理返回结果、不做翻译式恢复，认证也由独立配置负责，见[MCP 指南](mcp-services.md)。不能根据本页模型测试推断其全部链路。
- 凭据保护与内容策略是不同边界。分享日志前仍应主动检查，不把“普通日志移除凭据”理解成任意原文可公开。

遇到错误先保留提示，检查来源、JSON 格式、规则和模型可用性。不要为了让测试变绿而开放发送原文或换用没有配置策略的来源。
