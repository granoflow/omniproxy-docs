# 11 · 脱敏

脱敏是在文本发给外部来源之前进行的一次处理，不等于保证内容已经没有敏感信息。它按来源分别设置，默认关闭；本地模型调用不属于外发来源配置。首版不提供调用账本或学习派生数据的文本脱敏功能。

例如，你准备用外部模型翻译一段含联系人信息的文字，先为该来源开启发送前脱敏，再用非敏感样例测试。检查实际发送内容、上游返回与本机恢复后的译文，不要只看最终译文是否通顺。

> 自动脱敏可能漏检或误判。发送敏感内容前，请运行测试确认结果。来源 API key、代理 key、Authorization、密码和私钥始终不会写入普通日志，这项凭据保护不受本页开关影响。

## 为外部来源开启发送前脱敏

「脱敏」页直接列出已配置的外部模型、网络搜索和网页读取来源。勾选某一行的「发送前脱敏」后，OmniProxy 会对发给该来源的可解析文本运行标准规则。标准规则基于本机 Rust 引擎，负责识别结构化信息并确定性替换；它不是把整段内容交给模型改写。

每个来源还可以单独开启「允许请求跳过脱敏」。只有该来源已经开启「发送前脱敏」时才显示此选项；开启后，CLI 等调用入口可以在单次外部请求中明确传入 `redact: false`，发送该次原文。未传入 `redact` 时仍遵循来源设置；传入 `redact: true` 时强制脱敏。未允许跳过时，`redact: false` 应被拒绝，不会静默发送原文。UI 只负责设置和观察，CLI 发往外部来源的请求与其它入口统一由 Runtime 执行该策略；内部 gRPC 调用本身不经过内容脱敏。

同一来源只设置一次。它被用于普通模型调用、帮助、网络搜索或「用对话模型代替翻译模型」时，都服从这一设置。页面没有 egress 总开关，也没有「继承全局 / 覆盖全局」。新来源默认不勾选。

模型复核使用独立选择的本地模型，和来源的发送前脱敏开关分开设置。不选择复核模型时，仍可使用标准规则。

现有版本升级时，Runtime 会把每个既有来源在升级前实际生效的 egress 结果固化为该来源的显式勾选值，避免升级后静默扩大或缩小外发处理范围；旧复核选择仅在能够解析为已就绪、具备对话能力的本地模型时迁入独立选择，不把远程模型当作本地复核模型。

`Authorization`、代理密钥、API key、密码、access token 和 refresh token 等凭据字段始终不会写入普通日志或账本。答案缓存为了精确重放模型响应，以发行物私有密钥进行带认证加密；SQLite 只保存不可逆 HMAC key 和密文。密文被篡改、密钥不可用或解密失败时，Runtime 删除该项并按未命中重新请求，绝不回退为明文。这些是无条件安全边界，不是可配置的账本文本脱敏功能。

## 选择复核模型

脱敏页的模型选择器提供「不使用模型复核」选项和当前已就绪、具备对话能力的本地模型。选择仅用于脱敏复核，不会替你安装模型，也不把一个远程服务地址当作本地模型。

模型分段检查可能遗漏的信息并返回候选；最终确认、定位与替换由本机规则处理，不直接采用模型改写的整段正文。

| 情况 | 处理结果与下一步 |
|------|----------------|
| 不选择复核模型 | 使用标准规则；仍需检查处理结果 |
| 选择的本地模型可用 | 在标准规则之外执行复核，可能增加等待时间 |
| 所选模型暂不可用 | 保留选择并提示不可用，不自动换用其他模型 |
| 复核失败或不完整 | 保留标准规则处理结果，并显示复核未完整执行的信息 |

测试结果会报告复核是否实际运行、分段数、耗时和完整性。选择了模型不等于每次复核都成功，发送重要内容前应检查这项结果。

## 外部模型翻译的本机恢复

当已勾选的外部模型来源被用作翻译模型时，OmniProxy 会在本机为本次翻译生成不可预测的专属占位符，并把 Prompt、原文及命中词条中的敏感值替换后再发送。恢复映射只存在于可清零内存；严格术语最多一次重试会复用同一组占位符，恢复后的原文不会再次发给来源。

上游返回后，Runtime 会检查每个预期占位符是否恰好出现一次，并拒绝未知占位符。只有检查全部通过才在本机恢复原内容并显示最终译文。占位符缺失、变形、重复或未知时返回 `redaction_restore_incomplete`，不会猜测原位置或展示机械拼回的结果。映射在成功、失败或取消后立即清除，不写入请求/返回 JSON、普通日志、调用账本、缓存或数据库。

翻译调用详情中的「请求 JSON」是 adapter 实际发送的已脱敏 body；「返回 JSON」是实际上游返回的占位符 body；最终译文是单独的本机恢复结果。这三者不能互相冒充。

脱敏页还提供一个可重复运行的真实 JSON 测试器。你可以选择来源，修改测试输入 JSON 后点击「运行测试」。Runtime 会使用该来源的实际设置运行本地规则和所选本地模型复核；翻译模式会向所选来源发起真实请求，再在本机验证并恢复占位符。结果 JSON 会列出规则命中、实际外发、实际上游返回、本机恢复、复核状态与耗时。输入和结果都可以复制；页面显示不下时可以打开完整 JSON 弹窗继续编辑。

测试不会保存输入草稿或修改脱敏策略，但外部翻译测试会真实发送处理后的内容，可能产生延迟、费用和一条正常调用记录。输入错误只显示验证结果，不会发起模型调用或产生外部 attempt。

## 规则目录与用户覆盖

Runtime 始终带有一份只读默认规则文档。你可以下载完整默认文档和参考 prompt，再把它们交给任意 AI 模型协助阅读或填写。默认文档不会被删除或改写。

用户修改保存在另一份覆盖文档中。你可以上传覆盖文档，也可以在脱敏页直接打开编辑器手工修改；两种方式编辑的是同一种稀疏覆盖。校验通过后写入当前发行物 Internal State；换电脑或跨发行物复用时，必须显式导出并导入带 hash 的规则覆盖快照。来源级「发送前脱敏」勾选和允许名单仍只在本发行物。Runtime 不会持续把未校验的原文件当生效真值。

重新导入时，只有某条已知规则明确写有 `enabled: true` 或 `enabled: false` 才会改变其启用状态：

- 没有 `enabled`：保持现状。
- 删除整条规则：不表示删除或停用 Runtime 内置规则。
- 改写内置规则的正则、校验器或说明：不会修改 Runtime；导入结果会提示警告。

上传或手工编辑后都先运行验证和变更预览。预览会列出将应用的变更、未变更项目、警告与错误；只有全部有效的覆盖才会一次性生效。首版不接受新增规则、代码、动态插件、prompt 或其他 detector 定义。请审阅 AI 生成的内容后再应用；它只是协助，不替代你的判断。

## 允许名单

允许名单用于保留你已经确认无需替换的精确文本值。你可以在脱敏页查看、添加或删除这些值；Runtime 会在最终替换前应用允许名单。首版不把允许名单当成另一套规则系统，不接受正则、通配符、脚本或 detector 定义。

允许名单属于当前发行物的私有状态，不随模型文件一起共享。值在本机以带认证密文和私有 HMAC 保存，保护密钥来自系统凭据库。CLI 添加敏感值时使用标准输入，避免内容进入命令历史；GUI、CLI 和 gRPC/UDS 调用同一 Runtime 用例。保护密钥不可用或密文认证失败时，该值不会获得豁免，Runtime 会继续执行标准脱敏并提示允许名单暂不可用。

## 测试与边界

「运行测试」会执行真实处理并显示处理前后文本和按类别汇总的命中情况。标准目录以固定版本的
`pii` crate 为基础；额外规则优先来自国家标准、RFC 或固定版本的可信规则库（例如
Gitleaks 的秘密检测规则），并记录来源、版本、许可证与适配测试。确无合适上游的最小
项目补充会明确显示 `origin=omniproxy`，不会冒充第三方规则。当前 26 条规则中，25 条
来自锁定依赖、官方标准/资料或固定 Gitleaks 版本；只有窄范围的 `sk/rk/pk` API key
启发式因无法在现有适配器中保真移植 Gitleaks 的上下文、熵和允许名单而明确保留为
OmniProxy 补充。逐条证据见 `docs/redaction-rule-provenance.yaml`。

原始图片、音频、视频和其他未解析二进制内容不属于文本脱敏范围。raw 透传遇到这类正文时保持原始字节并返回 `non_text_unredacted` 警告；它不会把“未处理”冒充成“已脱敏”。需要发送此类内容时，用户必须自行确认风险。
