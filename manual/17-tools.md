# 连接第三方 AI 工具

先看工具是否支持你需要的自定义服务协议，再填写 OmniProxy 连接信息。一个工具允许改模型名称，不代表它允许改服务地址；能连通文本聊天也不证明全部 Agent 功能兼容。

## 在工具里找三个配置

| 字段可能的名称 | 从哪里取得 |
| --- | --- |
| Base URL、Endpoint、服务地址 | OmniProxy 监控台 |
| API Key、认证密钥 | OmniProxy 代理密钥，不是上游供应商密钥 |
| Model、Model ID | 实际模型列表复制的完整名称，或已启用的用途名 |

开始前确认来源和模型已验证。具体字段位置、地址是否需要 `/v1`、是否支持 Responses 或工具调用，以该工具当前官方文档为准。

## 完成一次接入

1. 按工具官方方式安装并打开工具，找到自定义模型服务配置。
2. 选择与 OmniProxy 当前入口相符的协议，填写三项连接信息。
3. 保存后选择一个已经验证的文本模型，发送一句短问题。
4. 到[监控台](02-monitor.md)找到请求，核对实际模型、响应和错误。
5. 接着测试你真正要使用的能力，例如图片、工具调用或结构化输出。

不要把客户端“设置已保存”当作接入成功；也不要因为一个简单请求成功就宣布整个 Agent 兼容。

## 工具在容器或另一台设备上

`127.0.0.1` 指工具所在环境自身。容器中的这个地址通常不是宿主机，另一台电脑也不是你的网关 Mac。使用工具或容器官方支持的主机访问方式，并核对监听范围、认证和防火墙。不要通过关闭认证解决地址问题。

另一台设备访问网关 Mac 时：

1. 在网关 Mac 的“监控台”先生成代理密钥，再打开“监听范围”，选择“所有网络”。确认状态已生效，记下实际端口。
2. 在 Mac 的“系统设置→网络”查看当前连接的局域网 IP。假设它是 `192.168.1.20`、实际端口是 `8080`，另一设备的 Base URL 可填 `http://192.168.1.20:8080/v1`；这两个数字必须换成自己的实际值，是否保留 `/v1` 仍由工具要求决定。
3. 两台设备应在可相互访问的网络中。工具带上代理密钥，发送短问题；回网关 Mac 的监控台查记录。连不到时检查地址、端口、网络隔离与防火墙是否允许这项连接，不关闭认证。
4. 不再需要跨设备访问时，把监听范围改回“仅本机”。

Docker Desktop 容器中的工具访问同一台 Mac，可按 [Docker 官方宿主机访问说明](https://docs.docker.com/desktop/features/networking/networking-how-tos/)使用 `host.docker.internal`，例如 `http://host.docker.internal:8080/v1`；端口仍换成监控台实际值，并携带代理密钥。这里访问的是宿主机上的网关，不需要把容器内某个应用端口误当作网关端口。其他容器运行环境不保证提供这个域名，使用其正式的宿主机访问方式。跨设备与容器路径没有在本次八项核心实测中验证，不把上述地址示例当成已验证的网络拓扑。

## 换模型而不改每个工具

首次接入成功后，可以把工具绑定到[固定用途入口](model-mapping.md)。以后先测试新目标，再在网关修改映射；工具继续使用原名称，但要重新核对实际结果和费用/隐私边界。

官网的工具目录适合查找工具和其接入指南；具体教程若标明“未实测”，不能据此理解为 OmniProxy 已验证兼容。手册这里说明共同操作，不维护另一份工具版本兼容清单。
